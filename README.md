# J.A.R.V.I.S — גרסת ענן רב-משתמשים

עוזר קולי אישי בעברית, רץ בענן (לא מקומי), עם חשבון נפרד לכל מי שמתחבר.
חי כרגע ב-**https://jarvis-cloud-oifj.onrender.com**.

> זו הגרסה **הרב-משתמשים** (fork נפרד שנבנה במיוחד בשביל זה). קיימת גם גרסה
> **חד-משתמשית** לשולחן העבודה, בתיקייה אחרת לגמרי על אותו מחשב — שני
> פרויקטים נפרדים, הקוד לא משותף ביניהם.

## שלושת עמודי התווך

1. **ניהול יומן ומיילים — השימוש המרכזי.** לא פיצ'ר נלווה: זו הסיבה
   שהאפליקציה קיימת.
2. **עוזר קולי שיחתי** — Groq (LLM עם tool-calling אמיתי, לא זיהוי מילות
   מפתח) + edge-tts, עם ממשק HUD בעברית (RTL) בדפדפן.
3. **סוכן גמיש לכל בקשה אחרת** — חיפוש באינטרנט, מזג אוויר, מניות, מחשבון,
   פתיחת דפי אינטרנט. (שליטה על מחשב שולחני — כמו Spotify או ציור ב-Paint —
   **לא קיימת בגרסה הזו בכוונה**: אין מחשב אחד מוגדר שהשרת אמור לשלוט בו;
   ראו את הגרסה החד-משתמשית לזה.)

## איך להשתמש בזה (משתמש קצה / בוחן)

פשוט להיכנס לכתובת למעלה ולהתחבר עם Google. **שימו לב:** חשבון ה-OAuth של
גוגל עדיין במצב **Testing** — רק כתובות Gmail שנוספו מראש תחת
Audience → Test users בקונסולת Google Cloud יכולות להתחבר. אם קיבלתם
"access blocked", זה לא באג — בקשו מבעל הפרויקט להוסיף את הכתובת שלכם.

אחרי ההתחברות: קריאת יומן/מייל מתחילה מיד, בלי לבקש רשות בכל פעם. **כל
פעולת כתיבה אמיתית (קביעת פגישה, שליחת מייל) תמיד ממתינה לאישור שלכם**
במודל — שום דבר לא נכתב ליומן או נשלח במייל בלי שתלחצו "אישור" בפועל.

## ארכיטקטורה, בקצרה

Flask + gunicorn, פרוס ב-Render (tier חינמי). Groq מריץ את הלולאה של
קריאות-לכלים (`app.py`'s `run_llm`); Google Calendar + Gmail הם ספק
היומן/מייל (Outlook/365 בנוי בקוד אבל לא מחובר לכניסה בגרסה הזו). נתוני
כל משתמש — חשבון, טוקן Google, תזכורות, משימות — נשמרים ב-Postgres
(פרויקט Neon חינמי) כדי לשרוד הפעלות מחדש של ה-tier החינמי; נופל ל-sqlite
מקומי כשאין `DATABASE_URL` מוגדר. תרשים מלא + הסברים ב-
[ARCHITECTURE.md](ARCHITECTURE.md); שפת העיצוב של הממשק (HUD) ב-
[DESIGN.md](DESIGN.md).

## מודל האבטחה: קריאה חופשית, כתיבה רק באישור

כל פעולה שיוצרת/שולחת/מוחקת משהו אמיתי — אירוע ביומן, מייל, קובץ, תהליך —
עוברת דרך אותו מנגנון confirm-to-act ב-[guardrails.py](guardrails.py):
JARVIS רק *מציע*, ומחזיר טוקן; שום דבר לא קורה עד שהמשתמש עצמו מאשר, וכל
בקשת אישור שמורה עם זהות המשתמש שביקש אותה (מונע מצב שמשתמש אחד מאשר
בטעות פעולה של משתמש אחר). ביקורת אבטחה מלאה (OWASP) בוצעה ומתועדת ב-
[security_report.md](security_report.md).

## הרצה מקומית (נדיר — הגרסה הזו מיועדת ל-Render, לא להרצה על המחשב שלך)

```bash
pip install -r requirements.txt
python app.py
```
נפתח על `http://127.0.0.1:5000`. ההתחברות היא **אותה זרימה בדיוק** כמו
בפרודקשן — "המשך עם Google" בדף עצמו; אין סקריפט התחברות נפרד. כדי שזה
יעבוד מקומית, צריך להוסיף את `http://127.0.0.1:5000/auth/google/callback`
כ-redirect URI מאושר על אותו לקוח OAuth מסוג Web application (אפשר
להוסיף כמה redirect URIs לאותו לקוח — זה לא מחליף את הכתובת של Render,
רק מתווסף לה). תעתיקו `.env.example` ל-`.env` ותמלאו את המשתנים
הרלוונטיים (`GROQ_API_KEY` לפחות; ראו את ההערות בכל שורה שם).

## פריסה משלכם על Render

1. **Google Cloud Console** (console.cloud.google.com): פרויקט חדש, הפעילו
   **Calendar API** ו-**Gmail API**. Credentials → OAuth client ID → סוג
   **Web application**, ה-redirect URI חייב להיות בדיוק
   `https://<שם-השירות-שלכם>.onrender.com/auth/google/callback`. תחת
   Audience → Test users הוסיפו כל כתובת Gmail שצריכה להתחבר (מצב Testing,
   ללא פרסום האפליקציה).
2. **Neon** (neon.tech, חינמי): פרויקט Postgres חדש, תעתיקו את מחרוזת
   החיבור (`DATABASE_URL`).
3. **Render**: "New +" → "Blueprint", הצביעו על הריפו הזה — Render קורא את
   [render.yaml](render.yaml) ומקים את השירות לבד. `render.yaml` עצמו
   מסביר בראש הקובץ מה חייבים להכין קודם (כולל להוציא מהערה שורות
   ב-`requirements.txt` שלא מתקינות על Linux).
4. בדשבורד של Render, תמלאו את משתני הסביבה שמסומנים `sync: false`
   ב-`render.yaml`: `DATABASE_URL`, `GROQ_API_KEY`, `GOOGLE_CLIENT_ID`/
   `GOOGLE_CLIENT_SECRET`, `FLASK_SECRET_KEY` (לייצר פעם אחת ולשמור קבוע
   בין פריסות), ואופציונלית `TAVILY_API_KEY`/`VAPID_*` (חיפוש מידע עדכני /
   התראות דחיפה — בלעדיהם האפליקציה עדיין עובדת, רק בלי הפיצ'רים האלה).

## מגבלות ידועות

- אין עדיין עריכה/מחיקה של אירוע יומן או מייל אחרי שנוצר — רק יצירה.
- מכסת Groq בחינם מוגבלת מאוד (נגמרת אחרי כ-6 פקודות בחשבון חדש) — לשימוש
  מתמשך צריך שכבת תשלום זולה של Groq.
- Outlook/365 בנוי בקוד (`microsoft_service.py`) אבל לא מחובר לזרימת
  הכניסה בגרסה הזו — Google בלבד כרגע.
- בדיקות ה-e2e (`e2e/redesign/`) רצות ב-Chromium בלבד — לא מוכיחות התנהגות
  ב-Safari באייפון אמיתי.
